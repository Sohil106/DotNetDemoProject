# Interview question coverage

This is a learning sample, not a claim that every interview question can be represented by one endpoint. The extracted list contains broad conceptual and experience questions. Runnable paths below are concrete demos; the remaining topics are grouped with the source areas to review or explain in an interview. Angular questions are excluded as requested.

## .NET topics to extend or explain

The sample is deliberately small enough to run locally. Use these source touchpoints to discuss the adjacent topics from the question sheet:

- **C# type/runtime and performance**: value/reference types, boxing, `StringBuilder`, `var`, `const`/`readonly`, nullable value types, `using`/`IDisposable`, casts, `ref`/`out`/`in`, `is`/`as`, partial/anonymous/static members, attributes, arrays vs `List<T>`, GC/finalizers, `dynamic`, top-level/global usings, file-scoped namespaces, unsafe/fixed buffers, generic variance/constraints, collection interfaces, local functions, expression bodies, null operators, switch expressions, equality/`IEquatable<T>`, `String.Intern`, spans/stackalloc, `Task` vs `ValueTask`, generators, deep cloning, sealing, volatile/Interlocked, caller attributes, struct/class, primary constructors, required members, default interface members, UTF-8/raw literals, JSON libraries, date/time zones, singleton safety, concurrent dictionaries, bit flags, culture/formatting, Guid/custom IDs, float precision and comparers. The sample shows selected modern constructs; these are best learned with focused unit-sized examples and trade-off explanations.
- **OOP/SOLID and patterns**: compare inheritance and composition; explain encapsulation, polymorphism, abstraction, overloading/overriding, interface multiple inheritance, diamond problem, Law of Demeter, immutability, design patterns, anti-patterns and tradeoffs. The service boundary is a starting point, not a full layered architecture.
- **ASP.NET Core**: use `Program.cs` for pipeline, service registration, options/config, controller vs minimal API discussion, CORS, limiter, auth, Swagger and health. File streaming, custom binders/filters, response caching, decompression, API version packages, reverse proxy forwarding, HTTPS certificates, AOT, gRPC, gateways, production deployment, distributed tracing and startup optimization depend on added packages or hosting choices and are not wired into this compact app.
- **EF Core**: switch to the SQL Server provider to explore real database behavior. Migrations, database-first scaffolding, concurrency tokens, soft-delete filters, owned/complex types, raw SQL, split/compiled queries, temporal tables, audit, JSON columns, TPH/TPT/TPC, connection retry, bulk extensions and production query plans require a real provider/schema/data volume. InMemory does not emulate relational constraints or SQL translation exactly.
- **LINQ and collections**: compare query syntax/method syntax, `First`/`Single`, joins, `SelectMany`, `Aggregate`, PLINQ, `ToList`/`ToArray`/`ToDictionary`, multiple enumeration, async EF operators, immutable/concurrent/sorted collections, pooling and large collection memory use. `IQueryable` code in the service is translated by the provider; LINQ in the learning controller is LINQ to Objects.
- **Async/DI**: compare `Task.WhenAll` with parallel CPU work, `ConfigureAwait`, synchronization context, deadlocks, `ValueTask`, `SemaphoreSlim`, thread starvation, cancellation propagation and background scopes. Use the singleton `DemoCounters` only for atomic counter demonstration; shared mutable service state should be designed carefully.
- **JWT/security**: real refresh rotation/revocation, secure secret storage, HTTPS, Identity/OIDC, authorization scope design, client storage, token key rotation, API-key auth and multi-service trust need a threat model and real identity/secret infrastructure.
- **SQL**: query plans, statistics, index fragmentation, deadlocks under load, isolation-level behavior, Always On, backups, full-text search and administration require SQL Server and realistic workloads.

## Deliberately out of scope

Angular is omitted. SQL Server is optional and not bundled; the default database is ephemeral EF InMemory. Production hosting, live distributed rate limiting, external OAuth/Identity, cloud deployment, reverse proxy and infrastructure monitoring cannot be demonstrated faithfully by a single local process. The included code is for learning and local practice, not production deployment.
